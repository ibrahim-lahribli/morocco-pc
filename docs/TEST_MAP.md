# Test Map

Which test pins which contract, in both directions — "is it safe to change this?"
is a lookup, not an archaeology project. Each row cites the file that enforces
the contract. Run everything with `npm run test:unit` (no DB needed; the test
count grows over time — check the current number, never cite a stale one).

## Data-semantics contracts

| Contract | Pinned by | What breaks if violated |
|---|---|---|
| NULL is never 0 (missing spec = UNKNOWN; explicit 0 = verified deficit) | `filtering/filter.test.js:737` "null is never 0" (and sibling PSU/GPU-connector cases in `compatibility/gpu-psu.test.js`) | Missing data becomes permissive; unsafe pairs silently PASS |
| Decision 27 cheapest-per-role reservation: per role, the first K-1 by Rule 3/5 order PLUS the cheapest eligible candidate by `selected_price`, ties by Rule 3/5 position, topped up to the unchanged cap; a bucket of n <= K is returned whole and consults no price at all | `retention/retain.test.js` — "the cheapest eligible candidate is reserved a slot", "the reserved set is re-emitted in Rule 3/5 score order", "an equal-price tie for the reservation is broken by Rule 3/5 position", "a single eligible candidate is never duplicated", "a REJECTed cheap candidate is never reserved", "a bucket that fits within K is returned untouched" | Retention silently shrinks below `min(K, eligible_count)`, or an unpriced candidate wins the reservation as if free and then fails every budget check |
| `budget_floor` semantics: `cheapest_total` sums `BUDGET_FLOOR_ROLES` = `EXPANSION_ORDER` minus GPU (the GPU is omissible under the OPTIONAL policy); a missing required role yields `null`, **never 0**, for both `cheapest_total` and `within_budget`; the field is present on every pass, empty builds or not | `retention/budget-floor.test.js` (19 tests) + `orchestrator/run.test.js` result-shape and zero-build assertions | A `0` floor reads as "everything is free" and `within_budget` reads true; or a GPU-inclusive floor reports "unaffordable" for a build that is serviceable without a discrete GPU |
| A budget-blind regression is visible without running a harness | `node scripts/measure-og01-reach.js --budget N --use-case U` prints `budget floor: <total> <ccy> vs budget N <ccy> (WITHIN/ABOVE)` on every run | The retained floor drifts again and is only noticed when a harness goes red — which is how OG-26 hid behind two raised budgets |
| `round2` half-up with shortest-decimal path (never `Math.round(x*100)` naively — `1.005` float trap) | `ranking/rank.test.js` (see `ranking/rank.js:66` for the documented pitfall) | Scores/rounding drift by a cent or a decimal between instances |
| deepFreeze ordering — seal children BEFORE the container | `scoring/build-score.test.js` (pitfall documented at `build-score.js:445`) | Frozen container exposes frozen-then-mutated internals; determinism violated |
| Determinism: tie-breaks are fixed code-unit compares (never `localeCompare`) | `ranking/rank.test.js` signature/tie-break assertions | Non-reproducible ranks across machines |
| Decision 16 gate: only FAIL prunes an assembly branch; UNKNOWN continues | `assembly/assemble.test.js` branch-gating cases | UNKNOWN pairs disappear instead of reaching scoring's penalty |
| Rule 11 high-TGP escalation: `board_tgp_watts >= 200` + NULL availability → FAIL `GPU_PSU_CONNECTOR_NULL_HIGH_TGP`, decided BEFORE the unknown-name branch; NULL requirements / unknown names / non-finite TGP stay UNKNOWN | `compatibility/gpu-psu.test.js:297–368`, `filtering/filter.test.js:808`, `assembly/assemble.test.js:1536` | The Decision 26 safety rule degrades back to UNKNOWN (or over-fires on UNKNOWN inputs) |
| `unknown_pairwise_count` is build-local, counted once per pair (Decision 23 O2) | `scoring/build-score.test.js`, `assembly/assemble.test.js` unknown-count cases | Double-counting silently over-penalizes builds (the W4 trap) |
| Candidate-level `unknown_pairwise_count` is computed but never read | documented in `retention/retain.js`; not pinned by a test — the W4 cleanup (status review Option D) is the real fix | Accidental revival would change every score |

## Boundary contracts (structural, not behavioral)

| Contract | Pinned by | What breaks if violated |
|---|---|---|
| `persistence/persist-ranked.js` stays write-only: no `require('pg')`, no `new Pool`, no `BEGIN/COMMIT/ROLLBACK`, no `SELECT`, no imports from other stages | `persistence/persist-ranked.test.js:162` banned-token list | Transaction control leaks into the writer; the single-write-transaction guarantee (Decision 19) erodes |
| Engine stage layout: one directory per stage, barrel `index.js` (persistence/ excepted, imported via `persist-ranked`) | `scripts/verify-docs.js` check 6 (`engine-layout`) + per-stage `index.test.js` | Barrels rot; boundary-only imports become unenforceable |
| Engine modules stay pure: no DB access, no clock, no randomness (DB lives only in loaders + orchestrator) | enforced by construction + `orchestrator/run.test.js` / `commit.test.js` transaction-boundary cases; the purity rule itself is `AGENTS.md` §5 | Unit suite can no longer run DB-free |
| Ingestion edge (`src/recommendation/ingestion/`) is impure-but-isolated: DB writes live only in `apply.js`, the caller owns the transaction, and no engine stage imports it | `ingestion/*.test.js` (pure logic) + the manual-import e2e on TEST (Decision 34) | Ingestion logic leaks into pure engine stages, or a write happens without a transaction |
| Offer natural key (Decision 34, OG-06): `store_offer` UNIQUE `(store_id, listing_identifier) WHERE listing_identifier IS NOT NULL`, plus a PARTIAL legacy `(store_id, product_id, product_variant_id) NULLS NOT DISTINCT WHERE listing_identifier IS NULL` | `database/migrations/017_offer_identity_and_provenance.sql` + the TEST functional probe (duplicate -> 23505, second listing allowed) | A price correction INSERTs a second offer instead of updating |
| Decision 35 seed-offer freshness exemption is default OFF and the offer class is snapshotted: a stale SEED offer (`ingestion_record_id IS NULL`) is eligible only with `options.allow_unverified_seed_offers === true`, a stale VERIFIED offer never is, a NULL/unparseable `last_checked_at` is never excused, and `build_component.offer_class` / `store_offer_id` are written inside the commit transaction | `offers/select.test.js` (option off/on, class + offer id on the carrier, params `[ids, currency, false]`) + `assembly/prices.test.js` + `persistence/validate-selected.test.js` (carrier shape) + `scripts/test-orchestrator-commit.js` §8 (mixed build, flip-the-offer does NOT relabel, residue 0) | A permalink's provenance label moves when the offer is later ingested — or the beta silently loses its default-OFF guarantee |

## Schema contracts

| Contract | Pinned by | What breaks if violated |
|---|---|---|
| At most one CPU / MOTHERBOARD / PSU / CASE / CPU_COOLER / SSD_BOOT per build candidate | `uq_build_component_role_singular` partial unique index (`database/migrations/011_reconcile_layer4.sql`), exercised by `scripts/test-layer4.js` | Multi-slot roles leak into builds the schema cannot represent (W10/K13) |
| Commit re-run guard: a query is committed exactly once; guards run after `SELECT … FOR UPDATE` on the query row | `orchestrator/commit.test.js` | Duplicate persistence; races between concurrent commits (reasoned, not concurrency-tested — U4) |
| Rejection writes are replace-idempotent per query (Decision 31, OG-33): the writer's FIRST statement is the scoped `DELETE … WHERE recommendation_query_id = $1`, then one INSERT per REJECT, same transaction; an `undefined` 4th argument means the writer is never invoked, an explicit `[]` clears stale rows | `persistence/persist-rejections.test.js` (statement-sequence pins: DELETE first, identical sequence on re-commit, DELETE-even-when-empty) + `orchestrator/commit.test.js` (3-arg = no `build_rejection` statement; 4-arg = DELETE + INSERT between guard 2 and COMMIT) + `scripts/test-orchestrator-commit.js` §6 (real rows, second connection: 3 identical zero-build commits hold 2 rows) | `build_rejection` double-counts under a legitimate re-commit — the exact "why was nothing recommended" query lies (the defect OG-33 measured 1 → 2 live) |
| A persisted rejection names its decisive partner (Decision 32, OG-32): the verdict carries `partner_product_id` (`partner_product_variant_id` for a variant-keyed partner) from the first FAIL pair of the decisive relationship, REJECT only; a PRODUCT-KEYED partner (id, NULL) is accepted while an orphan variant is refused | `filtering/filter.test.js` (product-keyed CASE partner, variant-keyed GPU partner read from both sides, PASS/UNKNOWN nulls) + `persistence/persist-rejections.test.js` (product-keyed insert params, orphan refused) + `scripts/test-orchestrator-commit.js` §7 (real row: non-null product id, NULL variant, both-ids FK, orphan refused before any statement, residue 0) | `partner_product_id` silently returns to NULL — the exact OG-32 defect, invisible to any row-count assertion since the rows still persist correctly |

## HTTP API contracts (`apps/api/`, Decision 36)

| Contract | Pinned by | What breaks if violated |
|---|---|---|
| The API owns no engine logic: `apps/api/src/engine.js` is the only module that may require `src/recommendation/**`, and only through stage barrels (`persistence/persist-ranked` is the one documented exception); `pg` is required only by `db.js` | `apps/api/test/unit/import-boundary.test.js` (every `require` under `apps/api/src` is resolved and classified) | Engine internals leak into the HTTP layer and become unenforceable; a second `pg` pool appears beside the engine's |
| POST and GET agree on every persisted field: POST re-reads the committed rows with the same statement GET uses; `budget_floor` and `engine_version` are POST-only facts (`null` on GET); `served_by.engine_version` is always the answering deploy; GET never re-runs the engine | `apps/api/test/unit/contract.test.js` (parity plus a null assertion per pass-only field) and `apps/api/test/db/recommendations.db.test.js` (real round-trip plus an engine spy proving zero engine calls on GET) | The two verbs become two implementations of one response and drift; or GET recomputes a floor and serves a number the pass never produced |
| `price_status` is derived, never stored: "verified" only when EVERY persisted component is `VERIFIED`, otherwise "indicative" (an unrecognized class included) | `apps/api/test/unit/contract.test.js` (mixed builds) plus `apps/api/test/db/recommendations.db.test.js` (the seed catalog is 100% `SEED_UNVERIFIED`) | An unverified price is displayed as confirmed |
| The option list and the POST validator are ONE vocabulary: `use_case` comes only from the active model's `gpu_required_use_cases`, an unadvertised value is a 422, and an unreadable model is a 503 rather than an empty array | `apps/api/test/unit/meta-consistency.test.js` (both directions), `apps/api/test/unit/contract.test.js`, `apps/api/test/db/recommendations.db.test.js` (OFFICE rejected against the real model) | A form offers a value the API rejects (or hides one it accepts); or a 503 renders as an empty form |
| Status codes: 201 only when builds exist; 200 for a zero-build pass and for `EMPTY_CANDIDATE_POOL` (which carries `reason`); 422 validation and vocabulary; 413 oversized body; 404 unknown OR malformed id; 429 rate limit; 503 no active model; 500 generic with `request_id` and no internal detail | `apps/api/test/unit/errors.test.js`, `apps/api/test/unit/rate-limit.test.js`, `apps/api/test/db/recommendations.db.test.js` | A valid zero-build answer reads as an error, or an internal message reaches the client |
| DB-free and DB-backed suites stay split: `test:api` needs no database; `test:api:db` fails fast (never skips) without a usable `TEST_DATABASE_URL` and treats zero executed tests as failure | `apps/api/test/run-db-tests.js` plus the two jobs in `.github/workflows/ci.yml` | The write-capable suite silently skips in CI and reads as coverage; a run proves nothing while exiting 0 |
| The API never writes the shared database by default: a start without `TEST_DATABASE_URL`, or one whose target normalizes to the shared host (a `-pooler` suffix stripped first), is refused | `apps/api/test/unit/db-guard.test.js` plus `db.js` reusing `scripts/lib/db-url.js` | `npm run start:api` writes Layer 4 rows to the single shared dev database |

## Where to add a pin

New engine behavior lands **with** a test in the owning stage's `*.test.js`
plus, when it changes a documented contract, a line here. The convention that
made the Decision 23 O2 work safe: find the pin first, change behavior, watch
the exact pin fail, update pin + decision together.
